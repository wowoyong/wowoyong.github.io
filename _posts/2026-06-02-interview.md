## 오늘의 면접 주제
> GitHub 트렌딩에 알고리즘 학습 저장소가 올라온 만큼, 기본기 면접에서 자주 나오는 정렬 알고리즘을 다시 볼 필요가 있습니다.

## 핵심 한 줄 요약
정렬 알고리즘은 시간 복잡도만 외우는 문제가 아니라, 데이터 특성, 메모리 사용량, 안정성, 최악의 경우를 보고 선택하는 문제입니다.

## 면접 질문 & 모범 답변

### Q1. 정렬 알고리즘이란 무엇인가요?
**기본 답변**: 정렬 알고리즘은 데이터를 특정 기준에 따라 순서대로 재배치하는 방법입니다. 숫자는 오름차순이나 내림차순으로 정렬할 수 있고, 객체는 나이, 이름, 생성일 같은 기준으로 정렬할 수 있습니다.  
**심화 포인트**: 면접에서는 “어떤 정렬이 빠른가”보다 “어떤 상황에서 어떤 정렬이 적합한가”를 더 중요하게 봅니다.

### Q2. QuickSort는 어떻게 동작하나요?
**기본 답변**: QuickSort는 pivot을 하나 고른 뒤, pivot보다 작은 값과 큰 값으로 배열을 나눕니다. 그 다음 양쪽 부분 배열에 같은 작업을 재귀적으로 반복합니다. 평균 시간 복잡도는 `O(n log n)`입니다.  
**심화 포인트**: pivot 선택이 나쁘면 이미 정렬된 배열에서 `O(n^2)`까지 느려질 수 있습니다. 그래서 실무 구현체는 랜덤 pivot이나 median-of-three 같은 방식을 사용합니다.

### Q3. MergeSort와 QuickSort는 어떻게 비교하나요?
**기본 답변**: MergeSort는 배열을 반으로 계속 나눈 뒤, 정렬된 두 배열을 합치며 정렬합니다. 항상 `O(n log n)` 성능을 보장하지만, 추가 메모리 `O(n)`이 필요합니다. QuickSort는 평균적으로 빠르고 메모리를 적게 쓰지만, 최악의 경우가 있습니다.  
**심화 포인트**: 단순히 QuickSort가 더 빠르다고 말하면 부족합니다. 배열 크기, 메모리 제한, 최악 성능 보장 여부를 함께 말해야 좋은 답변입니다.

### Q4. HeapSort는 어떤 상황에서 유용한가요?
**기본 답변**: HeapSort는 heap 자료구조를 이용해 가장 큰 값이나 작은 값을 반복해서 꺼내는 방식입니다. 시간 복잡도는 항상 `O(n log n)`이고, 추가 메모리는 거의 쓰지 않습니다.  
**심화 포인트**: HeapSort는 최악 성능이 안정적이지만, 실제 실행 속도는 QuickSort보다 느릴 수 있습니다. 메모리 접근 패턴이 좋지 않아 CPU cache 효율이 떨어지기 때문입니다.

### Q5. 안정 정렬과 불안정 정렬의 차이는 무엇인가요?
**기본 답변**: 안정 정렬은 정렬 기준이 같은 원소들의 기존 순서를 유지합니다. 불안정 정렬은 같은 값의 순서가 바뀔 수 있습니다. 예를 들어 학생 목록을 반별로 정렬한 뒤 점수로 안정 정렬하면, 같은 점수 안에서 기존 반 순서가 유지됩니다.  
**심화 포인트**: 숫자만 정렬할 때는 안정성이 잘 드러나지 않습니다. 하지만 객체 리스트를 여러 기준으로 정렬할 때는 안정성이 중요합니다.

### Q6. TimSort는 왜 실무 언어에서 많이 쓰이나요?
**기본 답변**: TimSort는 MergeSort와 InsertionSort의 아이디어를 섞은 정렬입니다. 실제 데이터가 이미 어느 정도 정렬되어 있다는 점을 활용합니다. Python과 Java의 객체 배열 정렬에서 사용됩니다.  
**심화 포인트**: TimSort의 장점은 이론상 평균 성능만이 아닙니다. 거의 정렬된 데이터에서 매우 빠르고, 안정 정렬이라는 점이 실무 데이터 처리에 잘 맞습니다.

### Q7. 정렬 알고리즘의 시간 복잡도는 어떻게 정리할 수 있나요?
**기본 답변**: QuickSort는 평균 `O(n log n)`, 최악 `O(n^2)`입니다. MergeSort, HeapSort는 최악에도 `O(n log n)`입니다. TimSort는 일반적으로 `O(n log n)`이고, 이미 정렬된 데이터에서는 `O(n)`에 가까울 수 있습니다.  
**심화 포인트**: 시간 복잡도 표를 외우는 것보다 최악의 경우가 왜 생기는지 설명할 수 있어야 합니다. QuickSort는 한쪽으로만 계속 나뉘면 재귀 깊이가 `n`이 됩니다.

### Q8. 실무에서 직접 정렬 알고리즘을 구현해야 하나요?
**기본 답변**: 대부분의 실무에서는 언어가 제공하는 정렬 함수를 사용합니다. 직접 구현하는 경우는 알고리즘 학습, 특수한 메모리 제약, 대용량 스트림 처리처럼 요구사항이 특별할 때입니다.  
**심화 포인트**: 면접에서 중요한 것은 라이브러리를 쓰지 말라는 뜻이 아닙니다. 라이브러리 정렬의 특성을 알고, 안정성이나 비교 함수 작성 실수를 피할 수 있는지가 중요합니다.

## 헷갈리기 쉬운 포인트
QuickSort는 항상 가장 빠른 정렬이 아닙니다. 평균적으로 빠른 편이지만, 최악의 경우와 pivot 선택 문제가 있습니다.

MergeSort는 in-place 정렬이라고 보기 어렵습니다. 일반적인 배열 MergeSort는 병합 과정에서 추가 배열이 필요합니다.

안정 정렬은 “정확히 정렬된다”는 뜻이 아닙니다. 같은 키를 가진 원소들의 상대 순서를 유지한다는 뜻입니다.

## 면접관 시각
면접관은 지원자가 복잡도 표를 외웠는지만 보지 않습니다. 왜 QuickSort의 최악 성능이 나오는지, 왜 MergeSort가 메모리를 더 쓰는지 설명할 수 있는지를 봅니다.

또한 실무 감각도 확인합니다. 정렬 기준이 여러 개인 객체 리스트에서 안정 정렬이 왜 중요한지 말할 수 있다면, 단순 알고리즘 암기를 넘어 실제 데이터 처리 경험이 있다고 판단할 수 있습니다.
