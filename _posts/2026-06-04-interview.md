## 오늘의 면접 주제
> 브라우저 게임, 개발 생산성, 웹 보안처럼 성능과 응답성이 중요한 주제가 많이 보였고, 그 기반에는 OS의 CPU 스케줄링 이해가 있습니다.

## 핵심 한 줄 요약
CPU 스케줄링은 여러 프로세스나 스레드가 CPU를 공정하고 효율적으로 나눠 쓰도록 실행 순서를 정하는 OS의 핵심 기능입니다.

## 면접 질문 & 모범 답변

### Q1. CPU 스케줄링이란 무엇인가요?
**기본 답변**: CPU 스케줄링은 Ready Queue에 있는 작업 중 어떤 작업을 CPU에서 실행할지 결정하는 과정입니다. 목적은 CPU 사용률을 높이고, 응답 시간을 줄이고, 작업 간 공정성을 맞추는 것입니다.  
**심화 포인트**: 단순히 “빠른 작업 먼저 실행”이 답은 아닙니다. 서버, 데스크톱, 실시간 시스템마다 좋은 스케줄링 기준이 다릅니다.

### Q2. FCFS는 어떻게 동작하나요?
**기본 답변**: FCFS는 First-Come, First-Served의 약자입니다. 먼저 도착한 프로세스를 먼저 실행합니다. 구현은 단순하지만 긴 작업이 앞에 있으면 뒤의 짧은 작업들이 오래 기다립니다.  
**심화 포인트**: 이 문제를 Convoy Effect라고 합니다. 예를 들어 10초 작업 뒤에 0.1초 작업 10개가 있으면, 짧은 작업들도 모두 10초 이상 기다립니다.

### Q3. SJF는 왜 평균 대기 시간이 짧다고 하나요?
**기본 답변**: SJF는 Shortest Job First입니다. 실행 시간이 가장 짧은 작업을 먼저 실행합니다. 짧은 작업을 빨리 처리하므로 전체 평균 대기 시간이 줄어듭니다.  
**심화 포인트**: 현실에서는 다음 CPU burst 시간을 정확히 알기 어렵습니다. 그래서 과거 실행 시간을 기반으로 예측합니다. 즉, SJF는 이론적으로 좋지만 실제 구현에는 추정이 필요합니다.

### Q4. Round-Robin은 어떤 상황에 적합한가요?
**기본 답변**: Round-Robin은 각 작업에 Time Quantum을 주고 번갈아 실행하는 방식입니다. 한 작업이 CPU를 오래 독점하지 못하므로 응답성이 중요할 때 적합합니다.  
**심화 포인트**: Time Quantum이 너무 짧으면 Context Switching 비용이 커집니다. 너무 길면 FCFS와 비슷해집니다. 그래서 적절한 Quantum 설정이 중요합니다.

```text
P1 4ms, P2 4ms, quantum 2ms
P1 -> P2 -> P1 -> P2
```

### Q5. Priority Scheduling의 단점은 무엇인가요?
**기본 답변**: Priority Scheduling은 우선순위가 높은 작업을 먼저 실행합니다. 중요한 작업을 빠르게 처리할 수 있지만, 낮은 우선순위 작업이 계속 밀릴 수 있습니다. 이를 Starvation이라고 합니다.  
**심화 포인트**: Starvation을 줄이기 위해 Aging을 사용합니다. 오래 기다린 작업의 우선순위를 조금씩 올리는 방식입니다.

### Q6. 선점형과 비선점형 스케줄링의 차이는 무엇인가요?
**기본 답변**: 비선점형은 실행 중인 프로세스가 CPU를 스스로 반납할 때까지 기다립니다. 선점형은 OS가 중간에 CPU를 빼앗아 다른 프로세스에게 줄 수 있습니다.  
**심화 포인트**: Round-Robin은 대표적인 선점형 방식입니다. FCFS는 일반적으로 비선점형으로 설명됩니다. 선점형은 응답성이 좋지만 Context Switching 비용이 발생합니다.

### Q7. CFS는 무엇이고 왜 등장했나요?
**기본 답변**: CFS는 Completely Fair Scheduler입니다. Linux에서 사용하는 스케줄러입니다. 각 작업이 CPU를 얼마나 공정하게 사용했는지 추적하고, 덜 실행된 작업을 우선 실행합니다.  
**심화 포인트**: CFS는 고정된 Time Quantum 중심이 아닙니다. vruntime이라는 값을 사용합니다. CPU를 많이 쓴 작업은 vruntime이 커지고, 적게 쓴 작업은 먼저 선택됩니다.

### Q8. CPU 스케줄링에서 처리량, 응답 시간, 공정성은 어떻게 충돌하나요?
**기본 답변**: 처리량은 단위 시간당 완료한 작업 수입니다. 응답 시간은 요청 후 첫 반응까지 걸린 시간입니다. 공정성은 여러 작업이 CPU를 지나치게 불균형하게 쓰지 않도록 하는 기준입니다.  
**심화 포인트**: 하나만 극단적으로 최적화하면 다른 값이 나빠질 수 있습니다. 예를 들어 짧은 작업만 계속 실행하면 평균 대기 시간은 줄지만 긴 작업은 굶을 수 있습니다.

## 헷갈리기 쉬운 포인트
SJF는 항상 “실무에서 가장 좋은 방식”이 아닙니다. 다음 실행 시간을 정확히 모르면 이상적인 선택을 할 수 없습니다.

Round-Robin은 항상 빠른 방식이 아닙니다. Context Switching이 잦아지면 실제 처리량은 떨어질 수 있습니다.

Priority가 높다는 것은 항상 먼저 끝난다는 뜻이 아닙니다. 선점 여부, Aging, I/O 대기, 커널 정책에 따라 결과가 달라질 수 있습니다.
