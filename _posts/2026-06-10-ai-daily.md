### Microsoft 오픈소스 도구가 해킹되어 AI 개발자 비밀번호 탈취에 악용됨

내용 요약:
- Microsoft의 오픈소스 개발 도구가 공격자에게 악용된 보안 사고입니다.
- 공격자는 AI 개발자를 대상으로 비밀번호와 인증 정보를 훔치려 했습니다.
- 관련 배경은 supply chain attack, developer tooling, credential theft입니다.
- 실무에서는 AI 도구를 설치할 때 출처 검증과 secret 관리가 더 중요해졌다는 의미가 있습니다.

개발자 코멘트:
AI 개발 환경은 이제 공격자에게 꽤 매력적인 표적입니다.  
API key, cloud token, GitHub token이 한 개발자 로컬에 모여 있는 경우가 많기 때문입니다.  
오픈소스 도구라고 해서 무조건 안전하다고 보면 안 됩니다.  
팀에서는 dependency pinning, secret scanning, 최소 권한 토큰을 기본값으로 가져가야 합니다.  
주니어라면 새 CLI나 extension을 설치하기 전에 repo 신뢰도와 recent issue를 확인하는 습관이 필요합니다.

### AI 스타 개발자들이 남긴 코드를 정리하는 일

내용 요약:
- AI를 활용해 빠르게 코드를 찍어내는 개발 방식의 후속 비용을 다룬 글입니다.
- 겉으로는 생산성이 높아 보여도, 유지보수성과 설계 품질이 떨어질 수 있다는 문제를 짚습니다.
- 관련 배경은 AI coding assistant, code review, technical debt입니다.
- 실무에서는 AI가 만든 코드도 결국 팀의 운영 자산이라는 점이 중요합니다.

개발자 코멘트:
AI로 코드를 빠르게 만드는 능력은 분명히 장점입니다.  
하지만 팀 개발에서는 “작동한다”보다 “이해되고 고칠 수 있다”가 더 중요할 때가 많습니다.  
AI가 만든 코드는 특히 중복, 과한 추상화, 숨은 edge case가 생기기 쉽습니다.  
리뷰어는 코드 양보다 변경 의도와 테스트 가능성을 먼저 봐야 합니다.  
주니어는 AI에게 구현을 맡기더라도 설계 이유는 직접 설명할 수 있어야 합니다.

agent 프로젝트를 볼 때는 “무엇을 자동화하는가”보다 “상태를 어떻게 유지하는가”를 먼저 봐야 합니다.

주니어라면 코드를 읽으면서 agent loop와 tool 호출 구조를 먼저 파악해보면 좋습니다.  
agent는 멋진 데모보다 반복 실행에서 깨지지 않는 구조가 더 중요합니다.
