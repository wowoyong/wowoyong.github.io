## 오늘의 면접 주제
> 개발자 생산성과 알고리즘 학습이 함께 주목받는 흐름에서, DP는 코딩 테스트와 기술 면접 모두에서 자주 나오는 핵심 주제입니다.

## 핵심 한 줄 요약
동적 프로그래밍은 큰 문제를 작은 문제로 나누고, 반복해서 계산되는 결과를 저장해 전체 계산량을 줄이는 방법입니다.

## 면접 질문 & 모범 답변

### Q1. 동적 프로그래밍이란 무엇인가요?
**기본 답변**: 동적 프로그래밍, 즉 DP는 복잡한 문제를 작은 하위 문제로 나누어 푸는 방식입니다. 이미 계산한 하위 문제의 답을 저장해 다시 계산하지 않습니다. 그래서 재귀나 완전 탐색보다 훨씬 빠르게 만들 수 있습니다.  
**심화 포인트**: DP는 단순히 “배열을 쓰는 알고리즘”이 아닙니다. 문제에 최적 부분구조와 중복 부분문제가 있어야 DP가 의미 있습니다.

### Q2. 최적 부분구조와 중복 부분문제는 무엇인가요?
**기본 답변**: 최적 부분구조는 큰 문제의 정답이 작은 문제의 정답으로 만들어지는 성질입니다. 중복 부분문제는 같은 작은 문제가 여러 번 반복해서 등장하는 성질입니다. 예를 들어 Fibonacci는 `fib(5)`를 구할 때 `fib(3)`이 여러 번 필요합니다.  
**심화 포인트**: 최적 부분구조만 있다고 DP가 되는 것은 아닙니다. 중복 계산이 거의 없다면 저장해도 이득이 작습니다.

### Q3. 메모이제이션과 타뷸레이션의 차이는 무엇인가요?
**기본 답변**: 메모이제이션은 재귀를 사용하며 필요한 값만 계산합니다. 타뷸레이션은 반복문을 사용해 작은 값부터 차례대로 채웁니다. 둘 다 계산 결과를 저장한다는 점은 같습니다.  
**심화 포인트**: 메모이제이션은 top-down 방식입니다. 타뷸레이션은 bottom-up 방식입니다. 면접에서는 “어떤 순서로 상태를 계산하는가”를 함께 설명해야 합니다.

### Q4. DP 문제를 만나면 어떻게 접근하나요?
**기본 답변**: 먼저 상태를 정의합니다. 그다음 점화식을 세웁니다. 마지막으로 초기값과 계산 순서를 정합니다. 예를 들어 계단 오르기 문제라면 `dp[i]`를 i번째 계단까지 가는 방법 수로 둘 수 있습니다.  
**심화 포인트**: 많은 지원자가 점화식부터 외우려고 합니다. 하지만 핵심은 `dp[i]`가 정확히 무엇을 의미하는지 정의하는 것입니다.

```js
dp[0] = 1
dp[1] = 1
for (let i = 2; i <= n; i++) {
  dp[i] = dp[i - 1] + dp[i - 2]
}
```

### Q5. DP의 단점이나 트레이드오프는 무엇인가요?
**기본 답변**: DP는 시간을 줄이는 대신 메모리를 사용합니다. 모든 상태를 저장하면 공간 복잡도가 커질 수 있습니다. 또한 상태 정의가 잘못되면 코드가 맞아 보여도 오답이 됩니다.  
**심화 포인트**: 모든 DP가 배열 전체를 저장해야 하는 것은 아닙니다. 이전 값 몇 개만 필요하다면 변수로 공간을 줄일 수 있습니다.

### Q6. 메모이제이션을 사용할 때 주의할 점은 무엇인가요?
**기본 답변**: 캐시에 저장할 key가 상태를 완전히 표현해야 합니다. 예를 들어 현재 위치와 남은 선택 횟수가 답에 영향을 준다면 둘 다 key에 포함해야 합니다. 하나라도 빠지면 다른 상황을 같은 문제로 착각합니다.  
**심화 포인트**: 재귀 깊이도 고려해야 합니다. 입력이 크면 stack overflow가 날 수 있어 반복문 기반 타뷸레이션이 더 안전할 수 있습니다.

### Q7. Greedy와 DP는 어떻게 구분하나요?
**기본 답변**: Greedy는 매 순간 가장 좋아 보이는 선택을 합니다. DP는 여러 선택지를 비교하고 그 결과를 저장합니다. 지금의 최선이 전체의 최선이라는 보장이 있으면 Greedy를 쓸 수 있습니다.  
**심화 포인트**: 면접에서는 Greedy가 틀리는 반례를 생각해보는 습관이 중요합니다. 반례가 쉽게 나오면 DP로 상태를 나누어 봐야 합니다.

### Q8. DP의 시간 복잡도는 어떻게 계산하나요?
**기본 답변**: 보통 상태의 개수와 각 상태를 계산하는 비용을 곱해서 계산합니다. 예를 들어 `dp[n][m]`이고 각 칸을 O(1)에 계산하면 O(nm)입니다. 각 상태에서 모든 이전 상태를 훑으면 더 커질 수 있습니다.  
**심화 포인트**: DP라고 항상 빠른 것은 아닙니다. 상태가 너무 많거나 전이 비용이 크면 최적화가 필요합니다.

## 헷갈리기 쉬운 포인트
DP는 재귀와 같은 말이 아닙니다. 재귀는 구현 방식이고, DP는 중복 계산을 줄이는 문제 해결 전략입니다.

메모이제이션은 무조건 더 빠른 방식이 아닙니다. 필요한 상태만 계산한다는 장점은 있지만, 함수 호출 비용과 재귀 깊이 문제가 있습니다.

타뷸레이션은 단순 반복문이 아닙니다. 하위 문제가 먼저 계산되도록 순서를 설계해야 합니다.

## 면접관 시각
면접관은 지원자가 유명한 점화식을 외웠는지보다 문제를 상태로 바꿔 설명할 수 있는지를 봅니다. 특히 `dp[i]`가 무엇을 의미하는지 말하지 못하면 풀이의 신뢰도가 낮아집니다. 좋은 답변은 상태 정의, 점화식, 초기값, 복잡도를 차례대로 설명합니다.
