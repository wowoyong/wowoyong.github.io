### AI 시대의 Script Kiddie 부상

내용 요약:
- AI를 이용해 보안 지식이 부족한 사람도 공격 도구를 쉽게 다루는 현상을 다룬 글입니다.
- 공격 코드 생성, 취약점 탐색, 사회공학 메시지 작성까지 AI가 진입장벽을 낮추고 있다는 점이 핵심입니다.
- LLM, 보안 자동화, prompt-based tooling이 배경에 있습니다.
- 실무에서는 개발 생산성뿐 아니라 보안 리스크도 같이 커진다는 의미입니다.

개발자 코멘트:
AI는 좋은 개발자만 강하게 만드는 도구가 아닙니다.  
공격자 쪽 생산성도 같이 올립니다.  
그래서 이제는 "우리 서비스가 복잡하지 않으니 괜찮다"는 판단이 더 위험합니다.  
주니어도 인증, rate limiting, secret 관리, audit log 같은 기본 보안 요소를 필수로 챙겨야 합니다.  
AI 도입 논의와 보안 설계 논의는 분리하면 안 됩니다.

> 📎 원문: [The Rise of the AI Script Kiddie](https://news.ycombinator.com/item?id=48282741)

### Google ADK, Kotlin 지원 시작

내용 요약:
- Google의 Agent Development Kit가 Kotlin에서도 사용 가능해졌다는 발표입니다.
- Android 환경에서 AI agent를 더 자연스럽게 만들고 앱 내부 워크플로우에 붙일 수 있는 방향이 핵심입니다.
- Kotlin, Android, Google AI stack, agent framework가 관련 기술 스택입니다.
- 실무에서는 모바일 앱도 이제 agent integration의 직접 대상이 된다는 뜻입니다.

개발자 코멘트:
지금까지 agent 개발은 Python 중심이 강했습니다.  
Kotlin 지원은 Android 팀이 별도 브리지 없이 AI 기능을 제품 안으로 넣기 쉬워졌다는 의미입니다.  
특히 모바일 앱에서 personal assistant, task automation, on-device interaction 시나리오가 늘어날 수 있습니다.  
풀스택 개발자라면 backend agent만 보지 말고 mobile client integration까지 같이 봐야 합니다.  
앞으로는 API 설계도 사람이 아니라 agent client를 같이 고려하게 됩니다.

> 📎 원문: [Google ADK now available for Kotlin](https://developers.googleblog.com/adk-kotlin-android-building-ai-agents/)

### 인간과 AI를 동일하게 다루는 실험적 프로젝트

내용 요약:
- Human과 AI를 같은 단위로 다루며 협업 구조를 설계하려는 오픈소스 프로젝트입니다.
- 사람과 agent를 하나의 작업 시스템 안에서 동등한 executor처럼 취급하는 아이디어가 핵심입니다.
- multi-agent orchestration, workflow engine, human-in-the-loop 설계가 배경입니다.
- 실무에서는 팀 협업 도구와 AI agent 운영 도구의 경계가 흐려지고 있음을 보여줍니다.

개발자 코멘트:
이런 프로젝트는 당장 프로덕션에 넣기보다 개념을 보는 용도로 가치가 있습니다.  
중요한 건 "AI를 보조 도구로 둘 것인가, 팀 구성원처럼 다룰 것인가"라는 질문입니다.  
실무에서도 이미 code review bot, support bot, data extraction bot이 역할 단위로 움직이기 시작했습니다.  
주니어는 agent를 호출하는 코드보다, agent에게 일을 나누는 구조 설계를 더 공부할 필요가 있습니다.  
앞으로 협업 시스템 설계 역량이 개발 생산성 차이를 크게 만들 수 있습니다.

> 📎 원문: [Show HN: Treats Human and AI the Same](https://github.com/haozeli2009/Hands-and-Claws)

### AI-Augmented Software Development Manifesto

- AI를 활용한 소프트웨어 개발 방식을 어떻게 정의하고 운영할지에 대한 선언문입니다.
- AI를 단순 자동완성 도구가 아니라 개발 프로세스의 일부로 재구성해야 한다는 관점이 핵심입니다.
- pair programming with AI, review workflow, software engineering practice가 배경입니다.
- 실무에서는 AI 사용이 개인 생산성 팁에서 팀 프로세스 문제로 이동하고 있다는 의미입니다.

개발자 코멘트:
이제 중요한 건 "AI를 쓰느냐"가 아닙니다.  
어떤 단계에서, 어떤 기준으로, 어떻게 검증하면서 쓸지가 더 중요합니다.  
코드 생성 자체는 쉬워졌지만, 품질 기준 없이 쓰면 팀 전체 유지보수 비용이 올라갑니다.  
주니어는 특히 초안 생성과 검증 책임을 분리해서 생각해야 합니다.  
좋은 팀은 AI 사용 규칙을 코딩 컨벤션처럼 운영하게 될 가능성이 높습니다.

> 📎 원문: [AI-Augmented Software Development Manifesto](https://ronanberder.com/ai-manifesto/)
